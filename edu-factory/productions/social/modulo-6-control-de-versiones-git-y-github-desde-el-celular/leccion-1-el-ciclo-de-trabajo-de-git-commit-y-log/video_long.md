## Intro (0:00 - 0:30)

**Gancho:**
«El ciclo status > add > commit» es lo que separa un resultado reproducible de uno que depende de la suerte. En esta lección (El ciclo de trabajo de Git: commit y log) lo vemos completo, con el proceso en pantalla.

**Presentación del problema:**
Problema real: principiantes absolutos, estudiantes y entusiastas de la tecnología que quieren programar desde su celular suelen bloquearse con El ciclo status > add > commit porque falta el orden de pasos. El flujo diario es ver (git status), preparar (git add) y guardar (git commit). git log registra la historia y git diff muestra qué cambió antes de confirmar. Hoy cerramos ese hueco en pocos minutos.

## Demostración práctica paso a paso

**Paso 1.** Ejecuta y muestra:

```
git status
```

**Paso 2.** Ejecuta y muestra:

```
git add .
```

**Paso 3.** Ejecuta y muestra:

```
git commit -m "Agrega mi primer proyecto"
```

**Paso 4.** Ejecuta y muestra:

```
git log --oneline
```

**Paso 5.** Ejecuta y muestra:

```
git diff
```

**Verificación.** Compara el resultado en pantalla con el esperado antes de avanzar.

## Errores comunes y cómo evitarlos

- **Saltarse «El ciclo status > add > commit».** Sin ese punto, el resto del proceso falla de forma silenciosa. Verifícalo antes de continuar.
- **Copiar comandos sin leerlos.** Revisa cada opción antes de ejecutar: un parámetro mal puesto cambia el resultado.
- **Practicar una sola vez.** En un nivel principiante a intermedio el proceso se consolida repitiéndolo hasta que salga sin guion.
